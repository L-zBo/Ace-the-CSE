# 解析块清洗改进与根因诊断（2026-08-11）

## 这轮做了什么

上一份交接文档判断「缺口 B 的瓶颈是解析块清洗（去页码、去水印、去跨页拼接残留）」。
**这个判断是错的。** 加细分诊断后，45 道 `no_clean_block` 里**没有一道**卡在长度上，
真正的卡点完全是另外三类。

这轮的主要产出是**根因诊断**（证明了哪些能救、哪些无解），修复只有 2 道。

## 修掉的一个真 bug

`repair_explanations_from_pdf.py` 的 docstring 写着证据链第 2 步是：

> 官方答案解析 PDF 里第 N 题块的结论 **== 库里 answer** —— 说明库里 answer
> 与官方一致，那么与之矛盾的现有 explanation 必然是串来的

**但代码里从来没执行这条检查**，而且会把 `answer` 一并改成块结论。这个脚本的
定位是「答案对、解析串了」，改答案需要跨源佐证，超出了它的证据链。

实测拦下 8 道，其中 3 道是江苏 2022 的**图形选项题**（选项全是 `[图形选项]`）：
新旧解析都在完整论证同一道题、只是结论不同，属于跨机构版本分歧，而且选项是图
无法独立复核。真让它改下去就是拿一家机构的答案覆盖另一家。

现在这类落 `answer_conflict`（8 道），交给 `fix_cross_paper_answers.py` 那条
有跨省佐证的路子。

## 新增的解析能力

### 1. 结论句式从 2 种扩到 7 种

原来只认「故正确答案为X」和「【N—正确答案X】」。实测江苏 2022 整卷用的是
「因此，选择D 选项」，5 道题因此判「无结论」。补齐后 `无结论` 13 → 3。

### 2. 新增第三类排版的切块器 `split_blocks_headed`

原有两个切块器只认「行首裸数字」和「【N—正确答案X】」。实测还有四种排版，
这些卷用行首数字切块只能切出 10 来个噪声题号（范围里混着 0 和 832），
**整卷等于没有解析可用**：

| 排版 | 卷 |
|---|---|
| `第【2】题正确答案:【B】` | 广西 / 海南 / 湖南 2023 |
| `第2 题` + `正确答案是：【B】` | 贵州 2023 |
| `【解析2—正确答案D】` | 河北 2024（放宽 `MARK_HEAD` 兼容「解析」前缀） |
| `【2】本题考查……` | 甘肃 2023 |

修好后广西/海南各切出完整的 1-110、湖南 1-120，无断号。

### 3. `well_indexed` —— 题号完整连续时放宽题面校验

`topical()` 要求解析块复述题干或选项，但相当一部分解析 PDF 根本不复述。
例：广西 2023 第 110 题库内题干只有「不能从上述资料中推出的是：」12 个字，
解析块直接从「A 项：根据文字材料」开讲，题面永远对不上。

当解析 PDF 的题号**从 1 开始、数量 ≥30、断号率 <10%** 时，题号本身就是可靠锚定。
再叠加另外两道已有保障——真题 PDF 那步已确认编号对齐、块结论必须等于库内 answer
——三者同时成立才放宽。

### 4. 同题号多块去重

三个切块器可能对同一题号切出多个块。结论一致时那只是切法不同，取最完整的；
结论不一致才算真歧义。`ambiguous_block` 8 → 5。

## 结果

`no_clean_block` 45 → 31，实际回填解析 2 道，`answer_vs_explanation` 96 → 94。

- `provincial_hainan_2020#109`（锂离子电池）317 → 790 字，旧解析在「可以在至」处
  被截断，新解析完整
- `institution_2022_b#067`（互动投影）706 → 275 字，旧解析后半串进别题的 D 项分析
  和错误结论「故正确答案为B」，末尾还挂着「70. 暂缺」；新解析短但全是本题的

两道修完后前端的「解析结论与答案对不上」提示条都消失了，浏览器实测确认。

## 剩下 100 道的根因（这才是本轮重点）

| 卡点 | 数量 | 能不能救 |
|---|---|---|
| `stem_not_anchored` | 26 | 部分可救，但受下面同一个数据模型问题拖累 |
| `align_failed` | 20 | ❌ **数据模型缺陷，当前无解** |
| `no_clean_block` | 31 | 见下表细分 |
| `answer_conflict` | 8 | ❌ 跨机构版本分歧，不该由本脚本改 |
| `ambiguous_block` | 5 | 真歧义，需人工 |

### align_failed 20 道：一个 JSON 混装多套卷

浙江 2023、江苏 2022、深圳 2020 这些卷，官方各有 **A/B/C 三份独立试卷 PDF**
（深圳是《思维能力测验》/《行测1》/《行测2》），而库内是**一个 JSON 文件**。
入库时「卷」这一维丢了，题号 1-N 混合了三套卷，任何单份 PDF 的题号链都对不齐，
`align` 要求「命中 ≥3 且错配 0」必然失败。

**这不是工具问题，是数据模型缺陷。** 要解决必须先拆卷（加 `examVariant` 字段
或拆成多个 JSON），属于数据模型变更，不该顺手做。上一轮删掉的 230 道同卷重复题
是同一个病根的另一个症状。

### no_clean_block 31 道细分

| 原因 | 数量 | 说明 |
|---|---|---|
| 题面对不上 | 15 | `well_indexed` 不成立且解析不复述题干，无从判定是不是串题 |
| 解析 PDF 无此题号 | 13 | 见下 |
| 多结论（串题） | 10 | 块里混着别题结论，**正确淘汰** |
| 无结论 | 3 | 该题在 PDF 里没有解析 |

「解析 PDF 无此题号」13 道里已查明的死因：

- **合集 PDF 缺该年份 4 道**：`material/` 里那几份叫「2018年-2024年事业单位联考
  职测（X类）笔试真题答案解析.pdf」的**实际只到 2023 年**——`institution_2024_e`
  全文「2024」出现 **0 次**。文件名骗人，库里的 2024 年事业编卷根本没有对应解析 PDF。
- **PDF 无文字层 3 道**：`national_2021_fushengjia` 的解析 PDF 只有 662 字、
  `provincial_henan_2021` 只有 441 字，是扫描件。要救得先 OCR。

## 一条不能改的东西

`sections()` 在年份匹配不上时返回**空列表**（整卷跳过），不要给它加
`or [text]` 的回退。事业编 PDF 是七年合集，回退到全文会让「第 8 题」在
2018-2023 里随便撞一个。`fix_options_from_pdf.py` 里那份带回退的实现是危险的。

## 复现

```bash
python scripts/repair_explanations_from_pdf.py            # 预览，报告含 why 细分
python scripts/repair_explanations_from_pdf.py --apply
python scripts/audit_full.py
```

逐题结论见 `reports/explanation_repair.json`，每条 `no_clean_block` 都带
`why` 字段说明具体卡在哪一关。

## 下一步建议

优先级最高的已经不是解析回填，而是**拆卷**：给同年多卷的省份恢复「卷」这一维。
它一次能松动 `align_failed` 20 道、`stem_not_anchored` 里的一部分、以及
上一轮 dedupe 遗留的同卷重复题判定。但那是数据模型变更，要单独规划。
