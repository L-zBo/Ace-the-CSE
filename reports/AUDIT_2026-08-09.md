## 三、已修复项详述

### 1. 客户端 bundle 62.5 MB → 1.35 MB

`questionLoader.ts` 原是自动生成的 2847 行文件，1381 条静态 import 把整个题库
打进客户端 bundle。所有调用方都是 `'use client'`，用户打开 `/practice` 就要下 62.5 MB。

改成两层：`questionIndex.ts`（同步元数据，1.27 MB 索引）+ `questionLoader.ts`
（按 paperKey `dynamic import()` 懒加载正文）。8 个调用方全部迁移。

| 指标 | 前 | 后 |
|---|---|---|
| 最大客户端 chunk | 62.5 MB | 1.35 MB |
| 单份试卷 chunk 中位数 | — | 38 KB |
| 共享基座 | — | 0.44 MB |
| dev 进程 RSS | 6,129 MB | 1,400 ~ 3,800 MB |
| 生产构建编译 | 15.9 min | 19.8 min（chunk 数 30 → 1412） |

> 代价：构建慢约 4 分钟。用一次性构建时长换用户侧 97% 下载量。

### 2. 选项顺序错乱 1,934 题 / 411 文件

`OptionList.tsx` 按数组顺序渲染，而数据里 label 序列是乱的，
其中 `A,C,B,D` 占 1,479 —— PDF 双栏 2×2 排版被按列读取的典型产物。

label 与内容配对完好，按 label 排序即可无损修复。脚本带两道保险：
- 重排前后 `(label, content)` 集合必须完全一致，否则 assert 中断
- 序列化格式与原文件字节级一致（CRLF + indent=2），否则拒绝写盘

**验证**：与 git HEAD 逐题比对 11,925 道，顺序变化 1,934 道，**内容改动 0 处**；
diff 为 8742 增 / 8742 删的纯换位。

### 3. 解析引流水印 804 题 → 0

用户在解析面板能直接看到「获取试卷更新，请关注公众号：gwyeasy…」。

只删**精确字面量**，不做关键词匹配 —— 题库里有大量含「关注」「公众号」的
正常内容（如「呼吁社会关注老年人的精神和心理需求」「关注公众号购买更便宜」
是江苏 2021 某题的正常选项），关键词匹配必然误删。

清理的字面量：`获取试卷更新，请关注` / `gwyeasy（公务员考试挺简单）…` /
`来源：X 整理：杨柳（微信：gwy288）` / `公众号：樱有尽有` /
`（认准淘宝：…，微信：…，公众号：…）` / `AS73982` 等，
以及独占一行的页眉 `20XX 国考《行测》（X）解析`。

**分三轮才清干净**：第一轮漏了选项字段，第二轮漏了「认准淘宝」变体。
最后 4 道上传者批注只摘掉联系方式、保留正文 —— 那句「此题有争议，
华图和粉笔答案不同」对做题的人有价值，不能连带删掉。

### 4. 解析串题污染 519 → 7

PDF 整块串行导致一道题的解析尾部粘着后面若干题，形如
`……故正确答案为 B。\n81.【答案】D\n【解析】……`。

截断规则（三条同时满足才切）：
1. 解析里出现 ≥2 次「故正确答案为」——一道题不会有两个结论，第二个必属他题
2. **首个**结论与本题 answer 一致（不一致的归入下面「答案存疑」，不在这里动）
3. 尾巴够长或带明确题号标记

512 道已截断，5 道因答案存疑跳过，2 道形态不明跳过。
其中 50 道截断后解析不足 40 字 —— 那些题的解析在 PDF 抽取时就基本丢了，
但展示邻题解析比展示得少更有害。

### 5. category 归位

`provincial-xinjiang-xingce-changshi-2021-006`（民法典常识题）被放在
`shuliang/provincial_xinjiang_2021.json` 里。题目 id 和 category 字段都是
`changshi`，错的是文件位置。已移入 `changshi/` 同名试卷（无题号冲突）。

### 6. 图形选项无图时的误导文案

`OptionList` 对图形选项渲染「选项 A（见上图）」，但有 17 道题根本没有题图，
用户看到「见上图」却找不到图。已加 `hasFigureImage` 判断，无图时显示
「选项 A（题图缺失，无法显示）」。

## 四、未修复项（需要人工或素材）

### 🔴 答案与解析结论矛盾 120 题 —— 已确认无法自动化

**试过官方 PDF 复核并失败**：写 `verify_answers_from_pdf.py`，用 `material/` 下官方
「答案及解析」PDF 按题干原文定位，**120 道只命中 4 道，且 4 道全不可信**：
两道匹配到了错误的类别（A 类题匹配到 E 类 PDF、E 类题匹配到 C 类 PDF），
一道题干只有「全国人大常委会」几个字，一道题干是「，，，，，（ ）。」的残缺数列题。

根因：答案解析 PDF 普遍**不重复完整题干**，只按题号列答案；而跨类重题会造成假匹配。
要自动化就得按「年份分节 + 题号」逐卷解析，46 套卷横跨国考/省考/事业编三种版式，
投入产出比不划算，且一旦错配就是把正确答案改错。**所以这批一道未动。**

已产出人工工单 `reports/ANSWER_CONFLICTS_WORKLIST.md`：按卷分组，每条给出
模块/题号/answer/解析结论/脏选项数/题干预览。其中 **118 道选项完好**（只需二选一核对），
**2 道选项本身是脏的**（整条记录要回源重建）。

（以下为首次审计原文：）

判定：解析中只出现一次「故正确答案为 X」，且 X ≠ `answer` 字段。

典型 `institution_2020_a` 第 005 题：
- `answer` = D，解析只分析 A 项且结论「故正确答案为 A」
- **选项 D 的内容是另一道地理题的完整选项**
  （`A．畜牧业是其支柱产业 B．气候特点是雨热不同期…`）

这类是 PDF 抽取整块串行，答案、选项、解析三者互不自洽，
**必须回源逐题核对，不能批量脚本修**。

集中卷：`institution_2023_c` 47、`institution_2023_e` 35、`institution_2023_b` 31、
`provincial_heilongjiang_2024` 25、`institution_2024_a` 23。

## 六、口径不一致：占位题 50 vs 55

`scripts/d17_list_unanswerable.py` 报 **50**，而 `src/lib/placeholder.ts`
（前端真正跑的那套）判定 **55**：

- d17 跳过带救援 marker 的内容，placeholder.ts 不跳
- placeholder.ts 认「暂缺」「缺失」这类短占位词，d17 不认

多出的 5 道经逐道核实确实不可作答（3 道题干选项全「暂缺」、1 道题干「缺失」、
1 道 4 个选项坏了 3 个）。**文档里长期记的「50 道」是低估，真实 55 道。**
索引 `question-index.json` 按 placeholder.ts 口径生成，与前端行为一致。
